## 0. שני עקרונות שמעל הכל

1. **אסור ששום דבר יישבר.** דומיננט (מספרת גברים, עסק השורש) חייבת להתנהג **בדיוק** כמו היום. לכן כל שינוי הוא **תוספת** עם ברירת מחדל = ההתנהגות הנוכחית: שדה `businessType` שברירת המחדל שלו `barber_men`, ומאחוריו כל ההתאמות. עסק בלי סוג = מספרת גברים = אפס שינוי.
2. **מתחילים בקטן.** שלב 0 הוא תשתית שלא משנה שום מסך; כל שלב אחריו נכנס מאחורי סוג‑עסק, נבדק על עסק דמו של אותו סוג, ורק אז נמכר.

## 4. הגבול בין המערכת לסוכן — מה המערכת בולעת ומה הסוכן לומד

> אפיון הסוכן נמצא במסמך נפרד: **`docs/PLAN-VERTICALS-AGENT.md`**, מוצמד לאותם שלבים (0–4). כאן רק הגבול.

**הכלל:** אם הלקוחה **לא צריכה להגיד או לשמוע** את זה — הסוכן לא יודע על זה. אם היא **כן** — זו יכולת סוכן.

| שכבה | המערכת בולעת (בלתי‑נראה לסוכן) | הסוכן לומד (יכולת שיחה) |
|---|---|---|
| שלב 1 | קטגוריות בתצוגה, "החל מ‑" כדגל על השירות | להגיד "החל מ‑" ולא לנעול מחיר; להציע מוצר אחד בסוף |
| שלב 2 | חישוב משך+מחיר מתוספות; חיפוש שתי עמדות במקביל | לשאול על תוספות (קצר); להציע קצב לתור הבא |
| שלב 3 | **חדרים** ושיבוצם; **באפר** ניקוי; **פירוק תור מורכב** לקטעים (צבע→המתנה→פן); מימוש חבילה אוטומטי | להגיד את משך הביקור הכולל; לשלוח הצהרה לפני; להזכיר יתרת סדרה; **לא לייעץ רפואית → הסלמה** |

**המשמעות למנוע השעות:** `get_available_slots` / `find_next_available` נשארים אותם כלים בדיוק. מבפנים הם מקבלים אילוצים חדשים (משאב, רצף, באפר) ומחזירים רק שעות שבהן **הכל** פנוי. הסוכן שואל "מתי פנוי?" בדיוק כמו היום.

## 5. מודל הנתונים — שינויים תוספתיים בלבד (כולם אופציונליים / ברירת מחדל = היום)

// Business
businessType   String  @default("barber_men")   // barber_men | hair_women | cosmetics | nails | ...

// Service — כולם אופציונליים; שירות קיים לא משתנה
category             String?   // "צבע", "טיפולי פנים", "מניקור"…
priceFrom            Boolean   @default(false)   // "החל מ-"

requiresResource     Boolean   @default(false)   // צריך חדר/עמדה
requiresIntake       Boolean   @default(false)   // צריך הצהרה לפני
defaultCadenceDays   Int?                        // קצב מומלץ לתור הבא

// חדש: תוספות לשירות (שלב 2)
model ServiceAddOn { id, businessId, serviceId, name, extraMinutes, extraPrice, isVisible }

// חדש: משאבים — חדרים/מיטות/עמדות (שלב 3)
model Resource { id, businessId, name, kind("room"|"station"), isActive, sortOrder }
// Appointment.resourceId String?   (שיבוץ בפועל)

// חדש: תור מורכב (שלב 2/3) — הצעה: קבוצה של תורים מקושרים, לא לשבור את Appointment

// קטע "processing" לא תופס את איש הצוות → מנוע השעות מתעלם ממנו בזמינות הצוות אבל כן תופס חדר.

// Appointment — קיים: staffNote. שלב 3: TreatmentNote מובנה (או JSON ב-staffNote)

### 6.1 ראיון ההקמה לפי סוג עסק — הקטלוג (צד המערכת)
